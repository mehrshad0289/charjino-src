# خط لولهٔ محتوای عمومی شارژینو

مرز داخلی/عمومی با **ساختار فایل** است، نه با پاک کردن چند عبارت بعد از نشت. منبع راهنما Markdown است؛ خروجی فروشگاه فقط JSON ساخت‌یافته + HTML محدود است.

## قرارداد فایل راهنما

H1 = عنوان عمومی.

فقط این H2ها عمومی‌اند (شمارهٔ فارسی/لاتین در عنوان نادیده گرفته می‌شود):

| کلید | عنوان‌های قابل قبول |
|---|---|
| `summary` | خلاصه، عنوان و خلاصه |
| `before_buy` | قبل از خرید بدانید |
| `fields` | اطلاعات لازم، اطلاعات لازم برای خرید |
| `purchase_steps` | مراحل خرید، مراحل خرید در شارژینو |
| `redeem` | فعال‌سازی، مراحل استفاده، مراحل فعال‌سازی، مراحل استفاده/دریافت در بازی |
| `errors` | خطاهای رایج، خطاهای رایج و راه‌حل |
| `faq` | سؤالات متداول، FAQ |
| `videos` | ویدیو، ویدیو آموزشی |
| `sources` | منابع |

هر H2 دیگر (از جمله «این محصول چیست»، «یادداشت ویراستار»، جدول slug، مقایسه با رقبا) **هرگز** وارد payload عمومی نمی‌شود. فایل `INDEX.md` راهنما نیست و ایمپورت نمی‌شود.

H3 داخل بخش عمومی فقط اگر نقش مشتری داشته باشد (مثلاً تب فعال‌سازی «PS5»). H3هایی مثل «سناریوی ویدیوی شارژینو» یا «عناوین موجود در این پلتفرم» داخلی‌اند و دور ریخته می‌شوند.

### یادداشت داخلی (اجباری از این به بعد)

Parser قبل از AST این‌ها را حذف می‌کند:

```markdown
<!-- internal -->
هر متن، جدول، لینک یا فهرست داخلی
<!-- /internal -->

:::internal
همان معنا به صورت بلوک
:::
```

نویسنده حق ندارد یادداشت داخلی را با «رقیب ننویس» یا نقل‌قول آزاد در بدنهٔ عمومی پنهان کند؛ باید داخل همین قالب باشد. جزئیات در `guides/BRIEF.md`.

## Parser

`league/commonmark` + GFM (جدول). استخراج `summary` / `steps` / `faq` / … از AST است نه regex روی کل فایل.

جدول Markdown در منبع فقط به دادهٔ ساخت‌یافته تبدیل می‌شود:

- `fields` و `errors`: ردیف → آیتم
- `videos`: فقط ردیف دارای URL آپارات/یوتیوب
- بقیهٔ جدول‌ها (slug، شمارش URL، فهرست کاتالوگ، استوری‌بورد) منتشر نمی‌شوند

تصویر `![alt](path)` فقط از بخش‌های `purchase_steps` و `redeem` و `fields` جمع می‌شود.

## HTML و لینک

رندر مجاز: `p, ul, ol, li, strong, em, a, h3, blockquote, code`.

لینک خروجی فقط اگر میزبان در `config/buy_guide.php` → `outbound_hosts` باشد (ناشر/پلتفرم رسمی + آپارات/یوتیوب). بقیه حذف می‌شوند (متن می‌ماند، `href` نه). همهٔ `<a>`های خروجی: `rel="nofollow noopener noreferrer"` و `target="_blank"`.

## توضیح محصول و SEO

یک `toPlainText`: حذف HTML/Markdown و فشرده کردن فاصله. همین تابع برای `meta description`، `og:description` و JSON-LD. صفحهٔ محصول توضیح را با همان رندر Markdown محدود نشان می‌دهد، نه `whitespace-pre-wrap`.

متن پیش‌فرض SEO وعدهٔ زمان تحویل («با تحویل فوری» / «تحویل آنی») ندارد.

## Validator (ایمپورت و ذخیرهٔ ادمین)

روی **خروجی عمومی** (نه کل فایل منبع) اجرا می‌شود. شکست اگر شامل باشد:

- `>` خام، `#` تیتر، `**`، بک‌تیک، جدول md (`|---|`)
- `INDEX.md`، `slug`، `appid`، «طبق فرم محصول»
- دامنهٔ خارج از لیست مجاز
- نام رقیب (bazelio، codashop، recharge، iranmojo، …)

ایمپورت آن راهنما را رد می‌کند و دلیل را گزارش می‌دهد. ذخیرهٔ راهنما/توضیح محصول در ادمین همان قوانین را دارد.

## کش

پس از ایمپورت موفق، تگ‌های `buy-guide:*` و صفحات محصول revalidate می‌شوند تا HTML کهنه سرو نشود.
